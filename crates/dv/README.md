# disccraft-dv

DV（ビデオカメラの 25 Mb/s と DVCPRO50 の 50 Mb/s の映像）のデコーダー: 1 フレーム（525/60 は 120 000 バイト、625/50 は 144 000
バイト。50 Mb/s はその 2 倍）から
絵（720 × 480 / 576、8 ビットの Y'CbCr）と音（16 ビットの 48 / 44.1 / 32 kHz、12 ビットの 32 kHz の音 1）を取り出す。
民生用の DV と DVCAM（IEC 61834-2。525/60 は 4:1:1、625/50 は 4:2:0）と DVCPRO（SMPTE 314M の 25 Mb/s。どちらも 4:1:1）、
DVCPRO50（SMPTE 314M の 50 Mb/s。4:2:2。M6.415）。
4:3 と 16:9（VAUX の表示モード）。フィールドの走査（VAUX のソースコントロールパックの IL と FS。M6.569）: インターレースで
フィールド 1（フレームの下のフィールド）が先、フィールド 2（上）が先、プログレッシブ。パックがなければ下が先。
AVI と `.dv` のファイル（M6.410）と `.mkv`（M6.416。craft-media の Matroska の読み取りのフレームの索引から）からフレームを
取り出すのは disccraft-transcode（`dv_source`）。MOV の DV は、FilmCraft の
メディアリーダーが disccraft-transcode の登録した `dv_decoder` でデコードする（M6.413）。

- 資料:
  - ITU-R BT.1618-1（2011-03。廃止扱いだが ITU のサイトで公開されている）: DIF の構造（Fig. 4、Table 1〜5）、VAUX の
    パック（Fig. 7、Table 13・14）、音の並べ替え（§1.6.2.2、Table 16 の AF SIZE）、マクロブロックとスーパーブロックの
    並び（§1.7.2.1 と Table 19、§2.1、Fig. 16・20・22・24・26）、DCT と重み（§2.2、Fig. 27）、クラスと量子化（§2.3、
    Fig. 28、Table 23）、可変長符号（§2.4、Table 24・25）、ビデオセグメントの 3 パス（§2.6）、エラーの印（§2.6、Fig. 33）。
    図は文書の .docx の EMF から読んだ。
  - SMPTE 314M-2005（2013 年に Stable。SMPTE のサイトで公開されている）: 同じ内容。表を突き合わせるのに使った。
  - US 5,585,930（特許、公開文書）: IEC 61834 の 625/50 の 4:2:0 のスーパーブロック（縦 12 × 横 5、それぞれ 9 × 3 の
    マクロブロック、列ごとに下・上と折り返す順）と、色差が 1 行おきであること。上の 2 つは 625/50 の 4:2:0 を定めない。
  - IETF draft-kobayashi-dv-audio12-00（1999）: 12 ビットの非線形の音と 16 ビットの対応（`audio::widen`）。
  - JVC GR-DVA10 のサービスマニュアル §2.5.5（公開されている）: 12 ビット・32 kHz の 4 チャンネルのモードでは、前半の DIF
    シーケンスが音 1、後半がアフレコ用の音 2（16 ビットの 2 チャンネルのモードでは前半が CH1、後半が CH2）。
  - 公開資料が見つからなかったもの（M6.411）: 44.1 / 32 kHz の 1 フレームのサンプル数の最小値（AF SIZE の基準。48 kHz は
    BT.1618-1 の Table 16）と、12 ビットの 2 つのサンプルの 3 バイトへの詰め方（1 バイト目と 3 バイト目の上 4 ビットが左、
    2 バイト目と下 4 ビットが右。並べ替えは 16 ビットと同じ式で、1 単位が 3 バイト）。ffmpeg に DV を作らせ（625/50 の
    44.1 / 32 kHz は ffmpeg が書ける）、こちらで書き換えた DV のフレームを ffmpeg がどう読むかを外から見て決めた（ルール 9 の
    外部オラクル。ffmpeg のソースは読んでいない）。最小値は 525/60 が 48 / 44.1 / 32 kHz で 1580 / 1452 / 1053、
    625/50 が 1896 / 1742 / 1264。12 ビットの 0x800 は誤りの印（前のサンプルを保つ。ffmpeg は 0 にする）。
- 表 25 の誤植: ITU と SMPTE の両方が (7, 1)・(8, 1) を `1110000s`・`1110001s`、(1, 16)・(1, 17) を `11111011110s`・
  `11111011111s` と 1 桁短く載せている（そのままだと (9, 1) の `11100010s` と前が重なる）。表 24 の長さ（8 と 12）から
  `11100000s`・`11100001s`・`111110111110s`・`111110111111s` に直した（単体テストで、すべての符号が表 24 の長さで、互いに
  前置にならないことを確かめる）。
- 他の DV の実装のソースは読んでいない（AGENTS.md ルール 3）。ffmpeg は外部オラクル（DV のファイルを作り、デコードした
  結果と比べる）としてだけ使った。
- 確かめ方: 単体テスト（符号表、走査順、量子化の表、スーパーブロックの配置が画面をちょうど 1 回ずつ覆うこと、逆 DCT が
  §2.2.1 の順変換を戻すこと、3 パスの読み出し）と、`tests/ffmpeg_oracle.rs`（ffmpeg が作った NTSC の 4:1:1、インターレースで
  2-4-8 の DCT を使う NTSC、PAL の 4:2:0 の 16:9 を、ffmpeg のデコードと比べて全フレームで PSNR 61 dB 以上、音はサンプル単位で
  同じ。壊れたフレームで panic しない）。音のほかのモード（525/60 の 32 kHz の 12 ビットと 16 ビット、44.1 kHz の 16 ビット、
  625/50 の 32 kHz の 12 ビット、44.1 kHz の 16 ビット）は、ffmpeg が作った DV の音をそのモードに書き換え、ffmpeg の読み取りと
  サンプル単位で同じ（`other_sound_modes_decode_as_ffmpeg_decodes_them`。12 ビットはすべての符号を通す）。
- 50 Mb/s（M6.415）: BT.1618-1 の Fig. 2（フレームは 2 つのチャンネル、それぞれ 10 / 12 の DIF シーケンス）、§1.7.2.1 と Table 18
  （チャンネル 0 がスーパーブロックの偶数行、1 が奇数行）、Fig. 19・21・25（マクロブロックは Y 2 つの 16 × 8、スーパーブロックは
  9 × 3 を列ごとに下・上）、Fig. 29（圧縮マクロブロックの Y0・Y1 のあとの X0・X1（読まない）と追加の AC の領域 E）、§2.6 の 4:2:2 の
  3 パス（2 パス目と 3 パス目は Y の領域の空きのあとに E を埋める）。VAUX の VS パックの STYPE 00100 で見分ける。音は CH1 / CH2
  （最初のチャンネルの前半と後半）。確かめ方: `fifty_megabit_dv_decodes_as_ffmpeg_decodes_it`（ffmpeg が作った NTSC（2-4-8 も）と
  PAL 16:9 の DVCPRO50 を、全フレームで PSNR 63 dB 以上、音はサンプル単位で同じ）。
- 音 2（M6.418、`decode_audio_pair`）: 12 ビットの 4 チャンネルのモードの音 2 は後半の DIF シーケンス（上の GR-DVA10 の
  資料）、DVCPRO50 の CH3 / CH4 は 2 つ目のチャンネル（BT.1618-1 の Fig. 2）。AAUX の音源のパックの音声モードが 1111 なら
  音はない。確かめ方: 12 ビットの音 2 が ffmpeg の 2 本目の音とサンプル単位で同じ、音を 2 組入れた DVCPRO50 の
  CH3 / CH4 も同じ（`dvcpro50s_second_pair_decodes_as_ffmpeg_decodes_it`）。
- サブコードのタイムコード（BT.1618-1 §1.4.2.2.1 の TC パック）は読まない: Encore も DV のフレームの中のタイムコードを読まない
  （M6.419、docs/encore-behavior.md 9.23）。
- まだないもの: DVCPRO HD。
