# disccraft-ffv1

FFV1（劣化のない映像の形式。テープの取り込みや保存用の映像で使われる）のデコーダー: AVI・Matroska・QuickTime に入った 1
フレームから、絵（Y'CbCr の 4:2:0・4:2:2・4:4:4・4:1:1・4:1:0、グレー、RGB、透明つき、8〜16 ビット）を取り出す。
版 0・1・3（版 2 は実験用で、RFC も扱わない）、Golomb-Rice の符号と範囲符号（既定の状態の表と独自の表）、版 3 の
スライスと CRC、キーフレームでないフレーム（前のフレームの適応の状態を引き継ぐ）。入れ物からフレームと設定のレコードを
取り出すのは disccraft-transcode（`own_source` / `own_video`。M6.562）。

- 資料:
  - IETF RFC 9043「FFV1 Video Coding Format Versions 0, 1, and 3」（2021-08）: 全部。標本の予測と境界（§3.1〜3.3、
    16 ビットの例外 §3.3.1）、量子化表と文脈（§3.4〜3.6）、色（§3.7。RGB の 9〜15 ビットの例外 §3.7.2.1）、範囲符号器
    （§3.8.1。状態の遷移表 Figure 24・25、数の読み方 Figure 21）、Golomb-Rice（§3.8.2。連続のモード §3.8.2.2、文脈の
    状態 §3.8.2.4）、ビット列（§4。パラメーター §4.2、設定のレコード §4.3、入れ物への入れ方 §4.3.3、フレーム §4.4、
    スライス §4.5〜4.9、CRC §4.9.3）。
- RFC がはっきり言わないことは、ffmpeg に作らせた FFV1（版 0・1・3、上の組み合わせを 26 通り。`tests/ffmpeg_ffv1.rs`）を
  こちらで読み、ffmpeg のデコードとビット単位で比べて決めた（ルール 9 の外部オラクル。ffmpeg のソースは読んでいない）:
  - 量子化表の組（§4.1）の範囲符号の状態は、表ごとに初めに戻す（5 枚で 1 つの状態にすると 2 枚目が 128 を超える）。
  - パラメーターの真偽の値（`chroma_planes` など）は、パラメーターの状態の配列の 1 つ目で読む。
  - Golomb-Rice へ切り替わる位置（§3.8.1.1.1 の sentinel）: 状態 129 の記号を 1 つ読んだあと、範囲符号器が読んだバイト数の
    1 つ手前から。
  - スライスの大きさ（§4.9.1）は、スライスの頭と中身の大きさ（終わりの部分は含まない）。最初のスライスは、フレームの
    キーフレームの印から始まる。
  - Cb と Cr は同じ文脈の状態を使う（量子化表の組の番号も同じ）。
  - 連続のモードの位置（`run_index`）は面ごと。ただし RGB（行ごとに面が交互）のスライスでは、全部の面で 1 つ。
  - 連続の長さと連続のモードは行ごとに初めに戻る。
  - AVI では、ffmpeg は BITMAPINFOHEADER の大きさ（biSize）に設定のレコードも含め、チャンクの終わりに詰め物の 1 バイトが
    つくことがある。設定のレコードは 40 バイトから biSize まで（disccraft-transcode の側）。
- 壊れたデータ: 読む数はすべて確かめる。絵の大きさは 8192 × 4320 まで、スライスは 4096 まで、文脈の状態は合計 1 GB まで。
  雑音と、本物のフレームを切ったものとビットを反転したもので、落ちないことを確かめている。
- craft-libs の craft-video にも FFV1 のデコーダーがある（feature `ffv1`）が、その説明のとおり版 3・範囲符号器・キーフレーム
  だけで、Golomb-Rice、版 0・1、キーフレームでないフレームは「対応していない」と返す（2026-11-28、6bfe8e7 の公開 API の説明で
  確かめた。実装は読んでいない）。DiscCraft はこちらを使い続け、足りない分を craft-video に入れるのは上流への提案の候補とする。
