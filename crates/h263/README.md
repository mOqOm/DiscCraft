# disccraft-h263

H.263（古い携帯電話の 3GP の動画や、初期のテレビ電話の映像）のデコーダー: 3GP・MOV・AVI・Matroska に入った 1 ピクチャ
から、絵（8 ビットの Y'CbCr 4:2:0、ITU-R BT.601 の水準）を取り出す。ベースライン（付属書のモードなし）の I ピクチャと
P ピクチャ、5 つの標準の大きさ（sub-QCIF 128 × 96、QCIF 176 × 144、CIF 352 × 288、4CIF 704 × 576、16CIF 1408 × 1152。
画素は 12:11）。GOB の頭（ある GOB もない GOB も）、マクロブロックの量子化の変化（DQUANT）、詰め物の符号。入れ物から
ピクチャを取り出すのは disccraft-transcode（`own_source` / `own_video`。M6.563）。

- 資料:
  - ITU-T H.263（01/2005。ITU のサイトで無料で公開されている）: 4 章（大きさと GOB、表 2・4）、5 章（ピクチャの層 §5.1、
    GOB の層 §5.2、マクロブロックの層 §5.3 と表 7・8・9・12・13・14、ブロックの層 §5.4 と表 15・16・17）、6 章（動き
    ベクトルの予測と境界の決まり §6.1.1・図 12、色差のベクトルの丸め 表 18、半画素の補間 図 13、逆量子化 §6.2.1、
    切り詰め §6.2.2、ジグザグ 図 14、逆変換 §6.2.4、足し合わせと切り詰め §6.3）、付属書 A（逆変換の精度）。
  - 表は PDF を文字にすると列がずれる（表 16 は (LAST, RUN, |LEVEL|, ビット数) と符号の列が別々に並ぶ）。各符号の長さを
    表のビット数と 1 つずつ突き合わせて書き起こした。
- 逆変換の計算のしかたは H.263 が決めていない（付属書 A の精度を満たせばよい）ので、定義どおりの倍精度の計算にした。
  ffmpeg が作った H.263（6 通り。`tests/ffmpeg_h263.rs`）を ffmpeg のデコードと比べると、どのフレームも PSNR 63〜71 dB
  （違いは逆変換の丸めだけ）。
- 扱わないもの（「対応していない」と返す）: 付属書のモード（D の制限のない動きベクトル、E の算術符号、F の進んだ予測と
  1 マクロブロック 4 ベクトル、G の PB フレームなど）と、版 2 の拡張したピクチャの種類（PLUSPTYPE。独自の大きさと付属書
  I〜T）。Sorenson の H.263（Flash の FLV）も別の形式。
- 壊れたデータ: 読む符号と数はすべて確かめる。ベクトルが絵の外を指しても端の画素で補う。雑音と、本物のピクチャを切った
  ものとビットを反転したもので、落ちないことを確かめている。
