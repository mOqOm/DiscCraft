# 残りの課題と予定

[English](open-issues.md) | 日本語

DiscCraft がまだできないこと、予定していること、確認に協力してほしいことの一覧。2026-11-23 時点（0.1.0 のアルファ）。
動いた / 動かなかったの報告を歓迎します。

状態の言葉の意味:

| 状態 | 意味 |
|---|---|
| 予定 | すぐ取りかかれる |
| 大きい | 予定しているが、大きな作業 |
| 判断待ち | 方針・費用・やり方の選択の判断を待っている |
| 依存先 | DiscCraft が使うライブラリ（craft-libs）の側の作業が要る |

| 実機 | 実際のプレーヤーやドライブでの確認が要る |
| 保留 | 公開資料を待っている（DiscCraft は公開された仕様だけから作っている） |
| 対象外 | 予定していない |

## 1. ディスクへの書き込み

DiscCraft は VIDEO_TS / BDMV のフォルダーと ISO イメージを書き出し、Windows ではビルドパネルの出力「ディスク」でディスクにも書き込む（M9.35）。

| 状態 | 項目 |
|---|---|
| 大きい | 2 層のディスク（DVD-9、BD-50）: イメージに入れた位置で層が切り替わるかを確かめる |
| 大きい | macOS と Linux での書き込み |
| 対象外 | 両面ディスク（Encore のビルドの「面」） |
| 実機 | Windows の書き込み（M9.35）を、ほかの種類の空のディスク（DVD+R、DVD-RW、DVD+RW、BD-R、BD-RE）で確かめる。DVD-R は書き込み、読み戻すとイメージと同じで、ドライブから PowerDVD で再生できた（M9.38、2026-11-23） |

## 2. Blu-ray と HD

| 状態 | 項目 |
|---|---|
| 実機 | Blu-ray の視聴制限（M6.543）: プレーヤーが持つのは 1〜8 のレベルではなく年齢なので、レベルを年齢に当てて（1 は全年齢、4 は 13 歳、7 は 18 歳など）ディスクとタイトルの頭で確かめる。DiscCraft のプレビューでは確かめたが、家庭用のプレーヤーでは未確認 |
| 依存先 | 2 つのフィールドが別々に動くインターレースの素材の、H.264 でのフィールドの予測（MBAFF かフィールドピクチャ）。DVD と Blu-ray のインターレースの形式（1080i、SD）への変換は、フィールドを分けたまま縮めて記録し（下のフィールドが先の素材もその順で）、MPEG-2 エンコーダーはマクロブロックごとにフィールドとして予測・変換する（使う価値のあるピクチャだけ。59.94p の映像から作ったインターレース素材でフレームより 0.1〜0.7 dB よく、効かない素材では差は 0.1 dB 以内）。H.264 のエンコーダー（craft-video）はインターレースのフレームをフレームとして符号化する。フィールドを符号化できる NVIDIA のカード（Blackwell 世代、RTX 50 シリーズ）でハードウェアエンコーダーを使うときは、1080i の H.264 をフィールドのピクチャとして符号化する（M12.51）。それ以外ではフレームのまま |
| 予定 | インターレースの変換を、実際のビデオカメラの素材（DV、AVCHD など）で測る（今は ffmpeg で作った素材で確かめている） |
| 取り込み待ち | インターレースの H.264（ビデオカメラやレコーダーの 1080i）のデコード: craft-libs の未マージのプルリクエスト [#1992](https://github.com/storytold/craft-libs/pull/1992) / [#2017](https://github.com/storytold/craft-libs/pull/2017)（フィールドピクチャと MBAFF）を取り込んだフォークで動いている |
| 取り込み待ち | 1080i の H.264 へのエンコード: フォークで動いている。craft-libs に [issue #2535](https://github.com/storytold/craft-libs/issues/2535) と [PR #2537](https://github.com/storytold/craft-libs/pull/2537)（#1992 の上に積んだドラフト）を出した |
| 判断待ち | DiscCraft のデコーダーが読めないものに、利用者が入れた ffmpeg を任意で使う（今の DiscCraft は ffmpeg を使っていない） |
| 実機 | 実機の Blu-ray プレーヤーが求めることのある HRD / SEI の細部 |
| 保留 | 4K（Ultra HD Blu-ray）のディスク: 映像の制約（HEVC Main 10、2160p、HDR10）は公開の論文にあるが、ディスクの構造の数値（プレイリストとクリップ情報の版、HEVC と 2160p の符号、HDR の欄）は公開資料になく、書き込み型のディスク向けの UHD の規格もない。HEVC Main 10 への変換（3840 x 2160 まで、BT.709）はできる（プロセッサーで毎秒約 1 フレーム、Windows の GPU で毎秒約 30 フレーム）が、`hevc` の機能を付けてビルドしたときだけ。公開するプログラムでは、特許を確かめるまで DiscCraft 自身の HEVC の符号化を外している。HDR10 と BT.2020 は、絵づくり（今は 8 ビット、BT.709）から変える必要がある |
| 対象外 | DTS-HD、Dolby TrueHD のそのままの収録（DTS-HD は確かめる素材がなく、TrueHD は Blu-ray では AC-3 を一緒に入れる必要があり、そのためのデコードと公開された仕様がない） |

## 4. 取り込みと速さ

| 状態 | 項目 |
|---|---|
| 予定 | DV（M6.410 から読める。フレームの中の音は 12 ビット・32 kHz も M6.411 から。DVCPRO50 は M6.415 から。ビデオカメラの音 2 と DVCPRO50 の CH3 / CH4 は M6.418 から 2 本目の音声のストリームとして）: DVCPRO HD は読めない |
| 依存先 | MXF（P2 カードのもの）の中の DV は絵が出ない: FilmCraft の MXF の読み取りが、デコーダーを求める前に DV を断るため、DiscCraft が渡す DV のデコーダー（M6.413 から `.mov` の DV に使う）まで届かない。AVI、`.mov`、`.mkv`（M6.416）、そのままの `.dv` の DV は読める |
| 依存先 | MPEG-4 Part 2（DivX / Xvid）の動画は、読み込めるが絵が出ない。DV（M6.410）のように DiscCraft で自前のデコーダーを作ることはできない: 仕様書（ISO/IEC 14496-2）が無料で公開されておらず（ISO の無料公開の規格の一覧にない。2026-11-23 に確認）、DiscCraft は公開された仕様だけから作り、ほかの実装のソースは読まないため。メディアリーダー（craft-libs）にデコーダーが入れば読める |
| 依存先 | ほかの古い形式の動画: WMV、HuffYUV、UT Video、QuickTime Animation の AVI / MOV / MKV は、読み込めるが絵が出ない（メディアリーダーにデコーダーがない）。PNG のフレーム（M6.561）、FFV1（M6.562。RFC 9043 から作ったデコーダー）、H.263（M6.563。ITU-T H.263 のベースライン。古い携帯電話の 3GP など）の 3GP / AVI / MOV / MKV は、DiscCraft が自分で読む。H.263 の版 2 の独自の大きさと付属書のモードは、まだ読めない。Hap、非圧縮の 10 ビット RGB（r210、R10k）、Theora（MKV の中と、音声のあるなしにかかわらず `.ogv`）は、craft-libs の映像のデコーダーで読む（M6.567）。WMV（M6.564 で調べた）: 版 9 の映像は VC-1 で、その規格は無料で読める（SMPTE の公開の文書庫にある SMPTE ST 421:2013）ので、DiscCraft が自分でデコードする道はある（大きなデコーダーになる。VC-1 は Blu-ray の映像の形式のひとつでもある。特許は 2026 年 11 月の時点で日本と欧州では切れているが、米国とブラジルにはまだ残る）。版 7・8 には公開の仕様がない。.wmv のファイルそのもの（ASF）は読めない: Microsoft の ASF の仕様書は、実装をオブジェクトコードでだけ配ることを許し、オープンソースのライセンスでは許さない。1998 年の公開の草案は、今のファイルが使わない前の版を書いたもの。HEVC（10 ビットも）、ProRes、DNxHD、VP9、AV1、Motion JPEG は読める |
| 対象外 | 元の動画のデコードを区間に分けて並べる: 測ると、スレッドを増やすと変換がかえって遅くなった（エンコーダーがすでに複数のコアを使う） |
| 大きい | GPU での変換の残り: Windows では HD の H.264（1080p / 720p の 1 パス）と HEVC（`hevc` の機能を付けたビルド）をハードウェアエンコーダーで符号化できる（環境設定。初期値はオフ。NVIDIA で 1080p の H.264 を毎秒 245 フレーム、画質はプロセッサー以上。色の記述 BT.709 も書く）。色の変換は全部のコアで並べて行い、ハードウェアでのビルドは約 2 倍の速さになった。さらに、ディスクと同じ大きさと色の素材（1080p の BT.709。Blu-ray の映像そのものなど）は、デコードした絵を RGB を通さずにそのままエンコーダーに渡すので、もう約 2 倍になった（Blu-ray の 1080p の映像で毎秒 114 → 218 フレーム）。2 パスもハードウェアで: 1 パスで作り、大きさのずれで平均を直してもう一度作るので、目標の約 1 % 以内に入り、画質はプロセッサーの 2 パスと同じかそれ以上で 4〜6 倍速い。1080i の H.264（1920 と 1440 × 1080）もハードウェアで: NVIDIA 自身のエンコーダーのインターフェース（NVENC）で、各フレームを 2 つのフィールドとして、素材と同じ順（上か下のフィールドが先）に符号化する。NVIDIA のエンコーダーは Media Foundation からはインターレースのストリームを断り、フィールドの符号化は NVIDIA の Blackwell 世代（RTX 50 シリーズ）だけなので、ほかのカードではプロセッサーのまま。60 秒の 1080i の Blu-ray が 10.5 秒（プロセッサーは 27.5 秒）で、画質は同じ。SD はプロセッサーのまま（MPEG-2 は DiscCraft 自身のエンコーダー）。大きさの違う BT.709 の素材（4K や 720p から 1080p など）も、RGB を通さずに面のまま拡大縮小する（4K → 1080p が毎秒 49 → 103 フレーム）。ほかの色の素材（BT.601 の SD、フルレンジ、10 ビット、4:2:2）も、RGB を通さずに面のまま色を BT.709 に移す（10 ビットの HEVC と ProRes 4:2:2 の 1080p が毎秒 80 → 164〜175 フレーム、フルレンジが 135 → 178、SD が 137 → 180 で色差の画質も上がった）。残り: macOS と Linux（VideoToolbox / VA-API）、実機のプレーヤーでの確認。BT.2020 と HDR、4:4:4、アルファのある素材は今も RGB を通る |
| 取り込み待ち | 大きな MKV のフレームの索引はメディアキャッシュに残し、読み通すのは 1 回だけ（以前は起動のたびに 18 GB で 15〜25 秒）。フォークで動いている。craft-libs に [issue #2534](https://github.com/storytold/craft-libs/issues/2534) と [PR #2536](https://github.com/storytold/craft-libs/pull/2536) を出した。MP4 はもともと速く開く |
| 取り込み待ち | トランスポートストリーム（`.m2ts` / `.ts` / `.mpg` / `.vob`）の索引はメディアキャッシュに残し、読み通すのは 1 回だけ（以前は起動のたびにファイル全体を読んだ。3.9 GB で 1.8 秒 → 2 回目は 0.01 秒未満、OS のキャッシュにあるとき）。フォークで動いている。craft-libs に [issue #2540](https://github.com/storytold/craft-libs/issues/2540) と [PR #2542](https://github.com/storytold/craft-libs/pull/2542) を出した（DiscCraft とは別のセッションで書いた） |

## 5. タイムライン・メニュー・パネル
