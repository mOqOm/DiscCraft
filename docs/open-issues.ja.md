# 残りの課題と予定

[English](open-issues.md) | 日本語

DiscCraft がまだできないこと、予定していること、確認に協力してほしいことの一覧。2026-11-22 時点（0.1.0 のアルファ）。
動いた / 動かなかったの報告を歓迎します。

状態の言葉の意味:

| 状態 | 意味 |
|---|---|
| 予定 | すぐ取りかかれる |
| 大きい | 予定しているが、大きな作業 |
| 判断待ち | 方針・費用・やり方の選択の判断を待っている |
| 依存先 | DiscCraft が使うライブラリ（craft-libs）の側の作業が要る |
| 取り込み待ち | DiscCraft では craft-libs のフォークで動いている。craft-libs へのプルリクエストが本家に入るのを待っている（入ったら本家に戻す） |
| 実機 | 実際のプレーヤーやドライブでの確認が要る |
| 保留 | 公開資料を待っている（DiscCraft は公開された仕様だけから作っている） |
| 対象外 | 予定していない |

## 1. ディスクへの書き込み

DiscCraft は VIDEO_TS / BDMV のフォルダーと ISO イメージを書き出す。ディスクに焼くのは、今は別のソフトに任せている。

| 状態 | 項目 |
|---|---|
| 大きい | Windows でビルド結果を DVD / Blu-ray に焼く（OS のディスク書き込みの機能を使う）。ドライブ・速度・枚数を選べるようにし、ビルドパネルの出力「ディスク」にする |
| 大きい | 2 層のディスク（DVD-9、BD-50）: イメージに入れた位置で層が切り替わるかを確かめる |
| 大きい | macOS と Linux での書き込み |
| 対象外 | 両面ディスク（Encore のビルドの「面」） |
| 実機 | 上のどれも、書き込みドライブと空のディスクでの確認が要る |

## 2. Blu-ray と HD

| 状態 | 項目 |
|---|---|
| 保留 | Blu-ray の視聴制限。DVD とは仕組みが違い（プレーヤーが持つのは 1〜8 のレベルではなく年齢）、ディスクのナビゲーションの命令がプレーヤーの設定を読む方法が、見つかった公開資料に書かれていない |
| 依存先 | 2 つのフィールドが別々に動くインターレースの素材の、H.264 でのフィールドの予測（MBAFF かフィールドピクチャ）。DVD と Blu-ray のインターレースの形式（1080i、SD）への変換は、フィールドを分けたまま縮めて記録し（下のフィールドが先の素材もその順で）、MPEG-2 エンコーダーはマクロブロックごとにフィールドとして予測・変換する（使う価値のあるピクチャだけ。59.94p の映像から作ったインターレース素材でフレームより 0.1〜0.7 dB よく、効かない素材では差は 0.1 dB 以内）。H.264 のエンコーダー（craft-video）はインターレースのフレームをフレームとして符号化する |
| 予定 | インターレースの変換を、実際のビデオカメラの素材（DV、AVCHD など）で測る（今は ffmpeg で作った素材で確かめている） |
| 取り込み待ち | インターレースの H.264（ビデオカメラやレコーダーの 1080i）のデコード: craft-libs の未マージのプルリクエスト [#1992](https://github.com/storytold/craft-libs/pull/1992) / [#2017](https://github.com/storytold/craft-libs/pull/2017)（フィールドピクチャと MBAFF）を取り込んだフォークで動いている |
| 取り込み待ち | 1080i の H.264 へのエンコード: フォークで動いている。craft-libs に [issue #2535](https://github.com/storytold/craft-libs/issues/2535) と [PR #2537](https://github.com/storytold/craft-libs/pull/2537)（#1992 の上に積んだドラフト）を出した |
| 判断待ち | DiscCraft のデコーダーが読めないものに、利用者が入れた ffmpeg を任意で使う（今の DiscCraft は ffmpeg を使っていない） |
| 実機 | 実機の Blu-ray プレーヤーが求めることのある HRD / SEI の細部 |
| 保留 | 4K（Ultra HD Blu-ray）のディスク: 映像の制約（HEVC Main 10、2160p、HDR10）は公開の論文にあるが、ディスクの構造の数値（プレイリストとクリップ情報の版、HEVC と 2160p の符号、HDR の欄）は公開資料になく、書き込み型のディスク向けの UHD の規格もない。HEVC Main 10 への変換（3840 x 2160 まで、BT.709）はできる（プロセッサーで毎秒約 1 フレーム、Windows の GPU で毎秒約 30 フレーム）が、`hevc` の機能を付けてビルドしたときだけ。公開するプログラムでは、特許を確かめるまで DiscCraft 自身の HEVC の符号化を外している。HDR10 と BT.2020 は、絵づくり（今は 8 ビット、BT.709）から変える必要がある |
| 対象外 | DTS-HD、Dolby TrueHD のそのままの収録 |

## 3. DVD

| 状態 | 項目 |
|---|---|
| 判断待ち | 国ごとに違う視聴制限のレベル（どの国にどのレベルを当てるか）。今 DiscCraft はどの国にも同じマスクを書く |
| 実機 | パレンタルブロックと視聴制限レベルを、家庭用のプレーヤーで（プレーヤーが国とレベルでマスクを引く。レベルを設定していないプレーヤーはブロックの最初の版を再生するとして作っている） |
| 判断待ち | マルチアングルのタイトル（Encore にはない機能） |
| 依存先 | VCD 形式の MPEG-1 のシステムストリームをメディアリーダーで開く（DiscCraft 側では回避済み） |

## 4. 取り込みと速さ

| 状態 | 項目 |
|---|---|
| 対象外 | 元の動画のデコードを区間に分けて並べる: 測ると、スレッドを増やすと変換がかえって遅くなった（エンコーダーがすでに複数のコアを使う） |
| 大きい | GPU での変換の残り: Windows では HD の H.264（1080p / 720p の 1 パス）と HEVC（`hevc` の機能を付けたビルド）をハードウェアエンコーダーで符号化できる（環境設定。初期値はオフ。NVIDIA で 1080p の H.264 を毎秒 245 フレーム、画質はプロセッサー以上。色の記述 BT.709 も書く）。色の変換は全部のコアで並べて行い、ハードウェアでのビルドは約 2 倍の速さになった。残り: デコードと縮小を速くしてハードウェアの速さを活かす、インターレース（1080i・SD）、2 パス、macOS と Linux（VideoToolbox / VA-API）、実機のプレーヤーでの確認 |
| 取り込み待ち | 大きな MKV のフレームの索引はメディアキャッシュに残し、読み通すのは 1 回だけ（以前は起動のたびに 18 GB で 15〜25 秒）。フォークで動いている。craft-libs に [issue #2534](https://github.com/storytold/craft-libs/issues/2534) と [PR #2536](https://github.com/storytold/craft-libs/pull/2536) を出した。MP4 はもともと速く開く |
| 取り込み待ち | トランスポートストリーム（`.m2ts` / `.ts` / `.mpg` / `.vob`）の索引はメディアキャッシュに残し、読み通すのは 1 回だけ（以前は起動のたびにファイル全体を読んだ。3.9 GB で 1.8 秒 → 2 回目は 0.01 秒未満、OS のキャッシュにあるとき）。フォークで動いている。craft-libs に [issue #2540](https://github.com/storytold/craft-libs/issues/2540) と [PR #2542](https://github.com/storytold/craft-libs/pull/2542) を出した（DiscCraft とは別のセッションで書いた） |

## 5. タイムライン・メニュー・パネル

| 状態 | 項目 |
|---|---|
| 判断待ち | テキストの枠のオーバーセットの「＋」から、別の枠へテキストを流す。Encore の資料では、はみ出したテキストは文字ツールで枠を広げて枠の中で流し直すもので、別の枠へ流す機能は見つからなかった。Encore にない機能を足すかどうか |
| 予定 | 自動ルートの残りの違い。Encore CS6 で測った規則に合わせ（M10.51 で全幅の帯とタイルの間の行き先も）、[#13](https://github.com/mOqOm/DiscCraft/issues/13) のメニューと確かめ用の配置を合わせた 696 本の矢印キーのつながりのうち 680 本が Encore と同じ。残りは、全幅の帯から下を押したときにどのタイルへ回り込むか（測った配置どうしで合う規則が見つかっていない）と、#13 のメニューの一部のページ（Encore の 2 回のビルドで答えが違う） |
