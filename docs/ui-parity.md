# UI パリティ（Adobe Encore に画面を寄せる）

> 節番号（§n）は [初期設計書](adr/0001-initial-design.md) と共通。実装順は [ROADMAP.md](../ROADMAP.md) の UI パリティ。

## 1. 前提（破ってはいけない線引き）

「互換性を保つ」のは **レイアウト・用語・操作系・作業フロー** だけ。AGENTS.md のルール 2 と 5 が優先する。

| やってよい | だめ |
|---|---|
| パネルの配置と作業の流れを参考にする | Encore のアイコン・ボタン・背景・サンプル・スクリーンショットを使う |
| 「プロジェクト」「モニター」「メニュー」「タイムライン」「フローチャート」「ビルド」という用語を使う | 参考画面をトレースする、または「似せた」描き直しをする |
| 実機で確認した操作手順を文章で出典つきで記録する | 「DVD」「Blu-ray Disc」のロゴを使う（説明的な名称の使用のみ可） |

`assets/` にアイコンやテンプレートを足すときは、すべてオリジナルかオープンライセンスにし、
横に `.attribution` を置いて `ATTRIBUTION.md` に 1 行足す（`cargo xtask assets` が検査する）。
当面はアイコンを使わず、テキストラベルと図形のみで構成する。

## 2. 画面構成（M6.14）

Encore CS6 の既定のワークスペースと同じ配置にした（パネルの位置と作業の流れだけを合わせ、見た目は egui の
ダークテーマのまま）。

```text
┌ メニューバー（ファイル / 編集 / オブジェクト / メニュー / タイムライン / 表示 / ウィンドウ / ヘルプ）                   ┐
│ ツールバー                                                         ワークスペース: [初期設定 ▼] │
├────────────────────────────┬───────────────────────────────┬────────────────┤
│ プロジェクト|メニュー|タイムライン|ビルド │ モニター|(メニュー名)|フローチャート   │ プロパティ|ディスク │
│ ┌──────┐ 選択中の名前・種類        │                               │                │
│ └──────┘ デュレーション・場所      │                               │                │
│ 名前 | 種類 | デュレーション         │                               ├────────────────┤
│ …                                   │                               │ レイヤー|ライブラリ │
│ [読み込み…] [新規 ▼]                 │                               │                │
├────────────────────────────┴───────────────────────────────┤                │
│ (タイムライン名)|(スライドショー名)    タイムラインビューア / スライドショービューア     │                │
├──────────────────────────────────────────────────────────┴────────────────┤
│ ステータスバー                                                                                 │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **タブグループ**: 5 つ。左（プロジェクト / メニュー / タイムライン / ビルド）、中央（モニター / メニュービューア /
  フローチャート）、右上（プロパティ / ディスク）、右下（レイヤー / ライブラリ）、下（タイムラインビューア /
  スライドショービューア）。`dock.rs` が描き、`workspace.rs` の `Layout` が表示と前面のタブを持つ。
- **ビューア**: メニュー / タイムライン / スライドショーを選ぶと、対応するビューアが前面に出る。別の項目を選んでも、
  最後に開いたものを表示し続ける。タブ名は開いているものの名前で、ないときは「(メニューなし)」などと出す。
- **ワークスペースプリセット**: 初期設定 / メニュー / ナビゲーション / ビルド の 4 種。ツールバーの右端と
  ウィンドウ ▸ ワークスペースで選ぶ。選んだプリセット、表示言語、最近使ったプロジェクトは
  `workspace.json`（Windows は `%APPDATA%\disccraft`、ほかは `~/.config/disccraft`）に保存する。
- **ウィンドウメニュー**: F キーなどでタブを前面に出す。前面に出ているタブのキーをもう一度押すと、グループを閉じる。
- **ステータスバー**: Encore にはないが、コマンドの結果を出すために最下段に置く。

### 2.1 起動時の画面（ようこそ画面）

プロジェクトを指定せずに起動すると、空の画面の中央に「ようこそ画面」を出す（`welcome.rs`）。

- 最近使ったプロジェクトの一覧（最大 10 件。押すと開く）
- 「新規プロジェクト」「プロジェクトを開く…」「新機能」の 3 つのボタンと、「終了」
- 「新規プロジェクト」（ファイル ▸ 新規 ▸ プロジェクト、Ctrl+N も同じ）は Encore と同じ構成のダイアログ
  （`new_project.rs`、M6.15）
  - 「基本」タブ: 「名前と場所」（名前は「名称未設定」を全選択した状態で開く。場所は最後に使ったプロジェクトの
    フォルダー、なければドキュメント。▼ で最近のフォルダー、参照… でフォルダーを選ぶ）と「プロジェクト設定」
    （オーサリングモード Blu-ray / DVD、テレビ方式、トランスコード設定の要約）
  - トランスコード設定の要約は DiscCraft が実際に使う値（MPEG-2 プログレッシブ、720×480 / 720×576、LPCM 48 kHz
    ステレオ、ディスク容量に合わせた自動ビットレート）。Encore の「トランスコードの初期設定…」に当たるプリセット
    編集はまだない
  - 「詳細設定」タブ: 縦横比（4:3 / 16:9）とディスク容量（DVD5 / DVD9、BD25 / BD50 / BDXL の BD100（3 層）/ BD128（片面 4 層）。M6.51）
  - OK で `場所/名前.dcproj` にすぐ保存する（場所が空なら後で保存先を選ぶ）
- Esc か背景のクリックで閉じると、空のプロジェクトのまま使える

Encore のロゴや製品の絵柄、ボタンの図柄は使わない（ルール 2）。文字とボタンだけで構成する。

### 2.2 見た目（M6.32）

読みやすさは Encore の画面の明るさの段階を目安にした（実機の画面で測った値。パネルの地 #404040、文字 #D6D6D6、
パネルの間の溝 #0D0D0D、タブの帯 #31〜#35、列見出しの帯 #4A〜#62）。色の値と描き方は DiscCraft で決めたもので、
アイコンや画像などの素材は使わない。実装は `crates/ui-egui/src/theme.rs`。

| 項目 | DiscCraft |
|---|---|
| 配色 | パネルの地 #3C3C3C、文字 #D8D8D8（見出し #F2F2F2、控えめ #9C9C9C）、パネルの間に 2px の暗い溝 #101010。OS が明るい表示でも暗い配色 |
| タブ | 暗い帯（#2B2B2B）に並べ、選択中のタブだけ地と同じ明るさで下の中身とつなげる。ほかのタブは控えめな文字 |
| 表 | 列見出しに明るい帯（#4C4C4C）、本体は 1 行おきに薄い帯、選択中の行は行全体を塗る |

### 3.0 Encore を参照するときの線引き

- 参照してよいのは、インストール済みの Encore CS6（日本語版）が画面に出す **文字** だけ。
  - 確認には、インストール先の UI 文字列（`Required/ja_JP/*.str`）を読む。
  - 使うのは、メニューの並び、項目名、既定のキー、用語。
  - ファイルの複製や、文章（ツールチップ、メッセージ）の流用はしない。
- 実行ファイルや DLL を逆アセンブル・逆コンパイル（Ghidra など）しない。理由は 2 つ。
  - AGENTS.md ルール 3（クリーンルーム）に反する。
  - Adobe の使用許諾にも反する。
- 出力ディスクの比較など、動かした結果を見るのは外部オラクルとして可（ルール 3）。
- 画面の見た目（アイコン、配色、スクリーンショット）は引き続き使わない（ルール 2）。
- 別の作業（2026-11-11 に渡された `Craft Anything/adobe-encore`）は、値の多くを Ghidra で Encore の実行ファイルと DLL から
  読み取っている。それらの値（ビットレートのプリセット、ディスク容量の選択肢、ボタン数の警告、メニューの合計サイズ、
  スライドと静止の時間の範囲、チェック項目の並びとコードなど）とその画面の参考画像は取り込まない。取り込んだのは、
  ここに書いた観察と Encore の文字列ファイル（用語）で確かめられるもの（モニターの拡大率とタイトルボタン、M6.43）だけで、
  コードは写さず書き直した。

## 4. プレビューの設計上の制約

`disccraft-vm` はビルド済みの `VIDEO_TS` を `load_video_ts` で読み、ナビゲーションだけを実行する（映像はデコードしない）。
したがって M6.8 のモニターは **ビルド後のディスク** を対象にし、映像面は `disccraft-menu` の静止描画と
メニューのハイライト状態の切り替えで表現する。Encore もプレビューにはレンダリングが必要なので、作業フローは一致する。

実装は `Session::preview` が `DiscModel` と現在の `Location` を保持する。キー操作のたびに
`Vm::restore(model, location)` で位置から復元して 1 キーぶん進め、また位置を保存する。
`Vm::restore` は pre コマンドを実行しない（ディスクはすでにその画面を表示している前提）。
`preview.*` は `journal: false` で、Undo にも dirty にも入らない。

リモコンキーは `up` / `down` / `left` / `right` / `enter` と、タイトルを終了させる `finish`。
メニュー復帰（`menu`）やタイトル再生（`title`）、前後チャプター（`next` / `prev`）は VM に
対応するキー操作がないため未実装（`finish` + メニュー操作で同じ場所へは移動できる）。

プロジェクトからの直接プレビュー（未ビルドのメニューを VM コマンドなしで操作する）は、
`vm` にプロジェクト駆動のモードを別タスクで足す。
